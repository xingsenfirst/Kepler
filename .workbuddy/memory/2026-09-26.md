## deploy.sh 审计与加固（用户要求：检查是否存在问题，然后修改）

按 `deploy-script-audit` 的做法，先写探针实测再改，改完每条修复补护栏 + 反向变异验证。

**确认的 4 处问题（均先复现、后修复）**

1. **Debian/Ubuntu 上站点配置会被写进 `modules-enabled` → 部署在 nginx 那步断掉**（最高影响）
   - 实测：用 Debian 真实 `nginx.conf` 形态跑 `nginx_detect_layout`，选中 `/etc/nginx/modules-enabled/kepler.conf`。
     该 include 位于 `http{}` 之外（main 上下文）→ `server{}` 非法 → `nginx -t` 报
     `"server" directive is not allowed here`。
   - 修复：新增 `nginx_http_include_dirs()`，只采信 `http{}` 直接内部的通配 include（awk 数括号深度，
     排除 `server{}` 内嵌套的 `include .../default.d/*.conf`），不再采信 http{} 之外的通配 include。
2. **`--mode docker` 下改管理员密码会静默写错**（真实 node 管道实测：`back\slash123` → 存成 `back\\slash123`）
   - 根因：`json_quote()` 先转义再经 stdin 传值，而内联脚本又做 `JSON.parse` 解码（且解析总是失败）。
   - 修复：删掉 `json_quote` 与 `JSON.parse` 分支，两条分支统一 `printf '%s' "$value"` 原样传值。
3. **RHEL 系 nginx 安装失败时 EPEL 兜底是死代码**
   - 实测：`pkg_install nginx` 失败即 `die_with_hint "软件包安装失败：nginx"`，
     后面的 EPEL 重试与整段对症提示（含 `--skip-nginx`）永远到不了。
   - 修复：改用不中断的 `pkg_run_pm`，先试装 → 补 EPEL → 再试 → 仍失败才走对症提示；并补上"已尝试"与日志关键行。
4. **`--domain example.com:8080` 被当成 IP 放行** → 静默改自签名证书 + `server_name` 带端口让 nginx -t 失败。
   - 修复：`collect_config` 里显式拒绝 `host:port` 并给出正确参数写法；IPv6 字面量不受影响。

**排除的一个"疑似缺陷"**：Ctrl+C 后锁残留 —— 实测 bash 5.3 下 SIGINT/SIGTERM **会**触发 EXIT trap，
锁会被清理，不是缺陷，未改。
