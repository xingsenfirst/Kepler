> 一款**多云对象存储**的本地管理工具：本地 Node.js 服务负责密钥保管、云端请求代理、加密与统计，浏览器端为原生 ES Module 前端（无构建步骤）。支持在同一界面中管理多家对象存储服务商的访问密钥与存储桶，所有密钥均以 AES-256-GCM 加密存储在本机。

**此为项目介绍与快速开始教程，开发文档因篇幅原因已分离，需二次开发请阅读 [Develop_Document.md](./Develop_Document.md)**

**一键部署**：把下面两行整段复制到终端执行：

```bash
curl -fLo /tmp/kepler-deploy.sh https://raw.githubusercontent.com/xingsenfirst/Kepler/main/deploy.sh \
  && sudo bash /tmp/kepler-deploy.sh
```
> 成功安装后，可在控制台任意位置执行 `kepler` 指令（需 root权限），进入数字选单，可执行更新、修改端口、修改初始管理员用户名、修改初始管理员密码及卸载操作。

<h1 id="readme-section1">一、功能特性</h1>

---

| 模块 | 能力 |
| --- | --- |
| **多云接入** | 统一管理多家对象存储服务商：腾讯云走原生 SDK，**Microsoft Azure Blob 走内置的 Shared Key + Blob REST 适配器**，其余厂商（阿里云 / 华为云 / 七牛云 / 又拍云 / AWS S3 / Google Cloud Storage / Cloudflare R2 / MinIO / Backblaze B2）一律使用内置 **AWS Signature V4 + S3 兼容协议**适配器（手写签名，零新增依赖）。各厂商要求的参数不同，界面按所选服务商自动切换字段名与提示：多数厂商只需密钥 + 地域（地域可为空时服务端补默认值），**Microsoft Azure 只需存储账户名 + 账户密钥（端点由账户名推导）、Cloudflare R2 需要账户 ID、MinIO 需要自建访问地址**（见下一节的「服务端点」说明）；每条密钥与存储桶均记录所属服务商与 Endpoint，可并存切换 |
| **密钥与存储桶** | 多访问密钥管理（本地加密保存、掩码回显、启用/停用、可见性、备注）、多存储桶管理（添加 / 从云端拉取 / 备注名外显 / **容量配额（管理员设置，服务端强制拦截）** / 可见性）、主备自定义域名、一键测试连接 |
| **文件管理** | 类资源管理器布局（地址栏 / 目录树 / 文件区 / 状态栏）、列表 / 大图标 / 小图标 / 缩略图四种视图、新建文件夹、上传（文件 / 文件夹 / 拖拽）、下载、重命名、移动、递归删除、多选与批量处理、属性面板、名称 / 类型 / 日期 / 大小组合搜索（可限定当前目录、支持续扫与请求取消） |
| **分片上传** | 大文件自动分片、3 分片并发、暂停 / 继续 / 取消 / 重试、断点续传（会话持久化，进程重启不丢失）、自动 `Abort Multipart Upload` 清理碎片 |
| **透明加密** | 三种方式：不加密 / crypto（AES-256-GCM 分段加密 + 逐段完整性校验）/ 文件头魔数（覆写文件头 + 流式异或，密文等长）；文件**本地加密后才上传**，云端控制台所见即密文；可选「查看密码」访问控制 |
| **分享链接** | 托管链接（有效期 / 次数 / 密码三重限制，可任意组合）或预签名直链；托管链接可审计**下载次数与最近下载时间**（不记录来源 IP —— IP 只出现在登录 / 解锁限流等告警日志中）；密文对象禁止生成直链。管理页列出每条链接的**分享者**与**所属存储桶**（均为创建时快照），便于追溯来源。对象在云端被删掉（站内删除或控制台等站外操作）后链接会被标记为「文件已删除」；把同名文件重新上传回**同一位置**即自动恢复有效 |
| **桶管理与监控** | 每桶容量 / 流量 / 请求数 / 碎片统计、一键清空、清理碎片、彻底删桶（空桶 + 无碎片 + 手输桶名三重校验）、存储用量环形图、近 7 天趋势、请求成功 / 失败与类型分布、操作日志 |
| **负载均衡（API Key 空间配额）** | 系统设置页的**管理员专属**卡片（位于「用户管理」与「文件加密」之间）：列出全部 API Key，逐个设置**最多可用空间**（填 0 为无限制）；并列出该 Key 下**每个存储桶的用量**（按大小排序、进度条、风箱式折叠展开）。**超出上限由服务端拦截**：以该 Key 新建存储桶、或它名下任一桶再上传 / 复制 / 移动（含 WebDAV 写入）一律 `403` 并在界面弹窗告知 —— 判定在所有写入出口生效，且计入「本次尚未回传官方统计」的待定增量，不会因统计缓存（15 分钟）而在窗口内偷偷超额。**存储桶自身的容量配额同样由服务端强制**（见上一行的「密钥与存储桶」）：两者是**两个层级**的额度（单桶上限 / 该 Key 名下合计上限），互不替代 —— 桶级超限回 `403 + code=BUCKET_QUOTA_EXCEEDED`，凭据级回 `403 + code=CREDENTIAL_QUOTA_EXCEEDED`，界面对两者分别给出可执行的出路 |
| **IP 访问屏蔽** | 黑名单（单 IP / CIDR，可按 HTTP 方法细化）、规则启停与命中统计、规则预检、一键屏蔽海外 IP、本机回环永久放行；作用范围支持**全局 / 单桶**两级，桶解绑时自动清理。规则维护为管理员专属：普通用户整卡不可见，且前端不发起规则列表请求 |
| **WebDAV** | 将当前激活的存储桶通过 WebDAV 挂载，仅 HTTPS + Basic 认证，多账户管理，透明加解密与元数据联动 |
| **用户与权限** | 首个用户为管理员（首次启动初始化），可增删用户并细粒度授权；**可将某个用户「封禁」**（管理员专有：填写封禁原因 + 选择到期时间，到期自动解除、也可随时手动解封）—— 封禁**立即吊销该用户全部会话**，且被封者登录时能看到封禁原因与解封时间；每用户并发会话上限、强制登出全部设备 / 指定用户；普通用户仅可查看与修改自己的资料，管理员入口（用户管理 / IP 屏蔽 / 操作日志等）对其整卡隐藏；存储桶由管理员统一维护，普通用户在「存储桶管理」中直接看到**管理员对其开放的全部桶**（只读：容量 / 流量 / 请求数 / 碎片），不提供「添加存储桶」入口 —— 他们无从得知桶名与地域，云端桶名亦属账号资产（仅管理员可枚举） |
| **Windows Hello 登录** | 用户可自行为账户启用 **WebAuthn（Windows Hello）** 二次验证：密码通过后自动唤起系统指纹 / 面容 / PIN，验签通过才签发会话。服务端用 Node 内置 `crypto` 实现 **ES256（ECDSA P-256 + SHA-256）** 校验与 CBOR/COSE 解析，零新增依赖；与 Google reCAPTCHA / Cloudflare Turnstile 串联共存、互不冲突 |
| **安全加固** | 部署模式强制 HTTPS、登录 / 加密密码 / 分享密码三处速率限制与锁定、CSRF 同源头校验、CSP 安全头、敏感数据加密落盘、全部持久化文件原子写入 |
| **支付设置** | 系统设置页内的「支付设置」卡片：总开关 + 渠道独立开关，按**各平台官方命名**分别登记支付宝 / 微信支付 / PayPal 的 API 凭证（`app_id`、`mchid`、`api_v3_key`、`client_secret` …），完成必填与格式校验并给出逐字段提示；另需填写**站点地址**（回跳与回调都基于它拼装） |
| **付费下载** | 单个分享链接可设置「需付费下载」与金额（人民币，最低 0.01 元）；下载者选渠道并完成支付后才取得下载权限，未支付 / 支付中 / 支付失败一律拦截。已接入**真实支付网关**：支付宝电脑网站支付（跳转收银台）、微信支付 Native（内置二维码）、PayPal Orders v2（跳转审批页）。总开关停用后所有付费链接自动转为免费，原配置保留 |
| **订单管理** | 侧边栏「订单管理」页按时间倒序列出全部付费订单：文件名 / 文件链接（一键复制，链接已删则标注）/ 订单号与商户单号 / 金额与支付方式 / 创建时间 / 付款时间 / 支付状态 / 是否已下载 / 退款操作；顶部汇总「共 N 笔 · 已收 ¥X · 已退款 ¥Y」。退款为记账动作（本系统不代持资金），标记后订单划线失效、凭证失效且不计入已收 |

>
> ⚠️ **自建 / 内网端点的安全策略**：MinIO 这类自建部署常用内网地址或回环地址，而本系统默认**拒绝**把服务端点指向回环、内网 / 链路本地 / 保留 IP 字面量（防盲 SSRF），也要求非回环端点必须走 `https://`。确需在内网使用，请在服务端显式设置 `ALLOW_PRIVATE_ENDPOINT=1`（内网 IP 字面量）与 / 或 `ALLOW_LOOPBACK_ENDPOINT=1`（本机回环）后重启；这两项只应在本机受控环境下开启。

<h2 id="readme-section4">1. 环境要求</h2>

---

- Node.js ≥ 18（推荐 20 及以上；S3 适配器依赖内置 `fetch`，热重载依赖 `--watch`）
- 仅三个运行时依赖：`express`、`cos-nodejs-sdk-v5`、`selfsigned`
- 测试与 lint 不引入运行时依赖：测试使用 Node 内置 `node:test`；ESLint 为可选开发依赖

---

<h2 id="readme-section5">2. 安装与启动</h2>

---

```bash
npm install
npm start        # 生产启动
npm run dev      # 开发模式（node --watch 内置热重载，改动自动重启）
npm test         # 运行测试套件（零依赖，Node 内置 test runner）
npm run lint     # 代码检查（ESLint 可选，未安装时给出安装指引）
```

> ⚠️ **跑测试前仍建议先备份 `data/`**：全部 store 都遵守 `COS_DATA_DIR` 隔离开关，且 `tests/helpers.js` 在**顶层无条件兜底**（凡是没有自己设 env 的测试进程，一律落进进程级临时目录）—— 这是第 13 轮改成的「默认安全」。此前是"靠每个用例自觉设 env + 用完还原"，而还原之后同文件里任何一次 `require`（含经 `cos.js` / 路由 / WebDAV 传递加载）拿到的都是绑定生产 `data/` 的实例；第 12、13 两轮都实测到 `npm test` 改写生产文件（`config.enc` 装着全部云厂商密钥与账户，`stats.json` 装着桶统计）。只要将来还有模块绕过这个开关，一次 `npm test` 仍会改写它们 —— 备份成本远低于恢复成本。

启动后控制台输出：

```
[Storage Manager] HTTP   : http://127.0.0.1:3000
[Storage Manager] HTTPS  : https://127.0.0.1:3443（自签名证书）
```

浏览器打开 <http://127.0.0.1:3000>（或自签名 HTTPS 端口）。服务默认**仅监听本机回环地址**，不对局域网开放。

> 若要使用 **Windows Hello**，请改用 <http://localhost:3000> 打开 —— `rpId` 必须是有效域名，以 `127.0.0.1` 这类 IP 字面量访问时部分浏览器会直接拒绝（详见下文「用户管理与 Windows Hello」）。

<h2 id="readme-section7">4. 一键部署脚本与 Docker 部署</h2>

---

在全新 Linux 服务器（Debian/Ubuntu、RHEL/CentOS/Rocky/Alma、Alpine、openSUSE）上跑一条命令即可完成部署：

```bash
curl -fLo /tmp/kepler-deploy.sh https://raw.githubusercontent.com/xingsenfirst/Kepler/main/deploy.sh \
  && sudo bash /tmp/kepler-deploy.sh --domain cos.example.com
```

脚本会自动安装 git / curl / Node.js 等依赖、从 `https://github.com/xingsenfirst/Kepler.git` 拉取源码、配置 Nginx 反代与 HTTPS 证书、注册 systemd 服务并做健康检查。**只需提供域名**，用户名与密码在打开页面后的首次初始化流程中设置。脚本幂等，重复执行等价于升级 / 修复。

> **CentOS 8 用户注意**：CentOS Linux 8 已于 2021-12-31 EOL，官方镜像站（含 `mirrorlist.centos.org`，2024-06-30 下线）不再为 8 提供仓库。典型症状是安装 `git` 时报 `perl-libs … is filtered out by modular filtering` —— **即使是全新安装的纯净系统也会中招**：这不是「模块流状态不一致」，而是 RHEL 8 的 module failsafe 按模块的包级过滤清单把 `perl-libs` 屏蔽掉了，所以 `dnf module reset perl` 那一套在干净机器上是**空转**。**脚本会自己修**，按「代价从小到大」逐档试：① 首选 `dnf install -y --setopt='*.module_hotfixes=true' <包>`（让仓库按**包级**视图参与求解、本次事务绕过模块过滤，**不改机器上任何持久状态**）；② 这一步不行才复位模块流并按报错里期望的流重新 `enable`（它会改**全局**模块状态，所以排在后面）；③ 仍不行才放宽候选版本（`--nobest`）。**绝不用 `--skip-broken`** —— 它会让「装不上」返回 0，脚本误以为装好了。手工等价命令就是第 ① 条（那个 `*` 的引号必须留，否则会被你自己的 shell 展开成文件名）。日志里 `Invalid configuration value: failovermethod=…` 是**无害警告**（旧版 yum 的选项，dnf 不认识），不是失败原因。长期建议迁到 Rocky / AlmaLinux。

安装完成会注册全局 `kepler` 命令，输入编号回车即可执行（也可直接 `kepler 4` 一步到位）：

| 编号 | 作用 | 说明 |
| --- | --- | --- |
| 1 | 重新安装 | 按已保存配置重新拉取源码并安装，数据目录不动 |
| 2 | 修改初始管理员用户名 | 停服后原子改配置，改完自动拉起 |
| 3 | 修改初始管理员密码 | 同上，密码经管道传入，不出现在命令行与日志里 |
| 4 | 修改应用端口 | 同步 `.env`、服务与 Nginx 反代配置 |
| 5 | 卸载 | 清理服务、应用、数据、证书配置与全局命令 |
| 0 | 退出 | — |

常用参数：`--domain`（必填）、`--port`、`--https-port`、`--http-port`、`--dir`、`--data-dir`、`--mode systemd|docker`、`--tls auto|acme|selfsigned|none`、`--mirror cn`（国内加速）、`--skip-node` / `--skip-deps` / `--skip-nginx` / `--skip-service`（自行接管某一步）。

HTTPS 证书默认向 **ZeroSSL** 申请（acme.sh 可用 `--email` 自动换取 EAB，零手工；走 HTTP-01 校验）。**不建议默认用 Let's Encrypt**：国内服务器经常连不上它的境外 API，而且它按「注册域名/公共后缀」7 天限发证书，公共后缀（如 `*.l.cd`、`*.github.io`）下所有人共享配额，极易被 `rateLimited`（429）限流，反复签不下来。

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `--ca zerossl\|letsencrypt\|litessl` | 选择 CA | 默认 `zerossl`；`litessl` 是亚数 TrustAsia 的免费 DV 证书，国内可直连 |
| `--eab-kid <KID>` | EAB 凭据 | LiteSSL 必需；到 [litessl.com](https://www.litessl.com) 注册后生成 |
| `--eab-hmac-key <密钥>` | EAB 凭据 | LiteSSL 必需；只经命令行交给 acme.sh，**不写入部署状态文件** |
| `--force-cert` | 强制重签证书 | 默认策略是「已装好且仍在有效期内的正式证书 → 重装直接跳过申请」，本开关压过该跳过 |

> 换 CA **不等于**换个接口地址：LiteSSL 与 ZeroSSL 的 ACME 接口都声明 `externalAccountRequired: true`，必须带 EAB（外部账户绑定）凭据。ZeroSSL 可由 acme.sh 用 `--email` 自动换取 EAB；LiteSSL 必须手工取。`--tls` 也可以直接写 CA 名，如 `--tls litessl`。
>
> 例（ZeroSSL，推荐，零手工）：`sudo bash deploy.sh --domain cos.example.com --ca zerossl --email you@example.com`
>
> 例（LiteSSL，国内直连）：`sudo bash deploy.sh --domain cos.example.com --ca litessl --eab-kid <KID> --eab-hmac-key <密钥>`
>
> 拿不到 EAB、又连不上其它 CA 时，先用 `--tls selfsigned` 把站点跑起来，之后再换正式证书 —— 证书步骤失败只会回退自签名，**不会**中断部署。
>
> **证书自检**：脚本不再只看「文件在不在」，而是要求证书**内容真的可用** —— 能解析出 subject / issuer 且都有实值、且与私钥配对。只判文件非空的实现会把「所有字段都是空白」的证书当成签发成功（`openssl req -x509 -subj "/"` 就会产出这种证书，`nginx -t` 也照样通过），用户拿到的是一个浏览器判定不安全、点开证书信息一片空白的站点。装完证书后脚本还会**核对「浏览器实际看到的是哪一份」**：带 SNI 连本机 HTTPS 端口取回实际证书、按 SHA-256 指纹与刚安装的文件比对。若两者不一致会直接点名原因（最常见的是用 `www.` 访问却只配了主域，于是退回到面板/旧站点在 443 上的 `default_server`）。自查命令：
>
> ```bash
> openssl x509 -in /etc/kepler/ssl/acme/fullchain.pem -noout -subject -issuer -dates   # 本地装的这份
> curl -vkI https://你的域名/ 2>&1 | grep -E 'subject|issuer'                          # 浏览器看到的那份
> ```
>
> 两者不一致时，按提示排查：① 访问的域名与配置的 `--domain` **完全一致**（含 `www.` 前缀）；② 停用面板/旧站点在 443 上的默认站点；③ 前面挂了 CDN 的话，证书要在 CDN 侧配置。

> 部署状态保存在 `/etc/kepler/deploy.conf`（0600）：修改端口、重新安装都以它为准，避免重跑时参数丢失；卸载会一并清除该文件。

若更习惯用镜像方式：

```bash
docker build -t cos-manager .
docker run -d -p 3000:3000 -p 3443:3443 -v cos-data:/app/data cos-manager
```

镜像基于 `node:22-alpine`，多阶段构建；以非 root 用户 `node` 运行，`tini` 作为 PID 1 转发信号，`/app/data` 声明为数据卷（**主密钥与配置都在此目录，务必持久化**）。`.dockerignore` 已排除 `data/`，不会将本机密钥打入镜像。

<h2 id="readme-section11">2. 断点续传</h2>

---

- ≤ 8MB 直传；更大文件自动分片（8MB 起步、按大小自适应），单文件 3 分片并发。启用「文件头魔数」加密时分片固定为 **5MB**（该模式的密钥流是同步生成的，分片越大越会卡住服务；5MB 同时也是 AWS S3 要求的分片下限，不能再小）。
- 上传中暂停、刷新页面或服务重启后，再次上传同一文件（同路径同大小）会自动对齐云端已传分片并续传。
- 取消任务会调用分片中止接口清理云端分片，避免产生无用存储费用。

<h2 id="readme-section12">3. 文件加密</h2>

---

在「系统设置 → 文件加密」选择：

- **不加密**（默认）：明文直传，行为与普通对象存储客户端一致。
- **crypto（AES-256-GCM）**：分段高强度加密，密文任何篡改 / 损坏都会在解密时被完整性校验拦截；密钥为首次启用时生成的 `data/enc.key`，**务必备份，丢失后密文无法解密**。
- **文件头魔数**：轻量混淆——仅覆写文件头为自定义魔数（默认 `ENCRYPTED`，支持十六进制或文本，1–64 字节），其余内容流式异或；随机盐默认开启（每文件独立盐）；密文与原文等长，被覆写的原始文件头保存在本地元数据中。
  - ⚠️ **它是混淆级保护，且性能显著低于 crypto**：密钥流每 32 字节做一次 SHA-256、在单线程里同步生成，因此大文件会明显拖慢服务（分片上传已据此压到 5MB 一片）。要真正的内容保密 + 完整性校验，请用 `crypto`（AES-256-GCM 走原生实现，无此问题）。

其他规则：

- 加密文件列表显示 🔒 徽标，缩略图显示「已加密」占位图，属性面板显示原始大小。
- **查看密码**（可选）：设置后，**管理端 `/api/**` 与分享页 `/s/…`** 查看 / 下载加密文件前须验证，通过后获得 30 分钟有效的 HMAC 令牌；管理端只从 `x-enc-token` 请求头读取该令牌，分享页另发一枚 `HttpOnly`、`path=/s/` 的 Cookie 复用（不进入 `/api/**`）；**WebDAV 挂载（`/dav`）不叠加这道门禁**，它由独立的 Basic 认证与 IP 守卫把关，凭据须由管理员授予。密码以 scrypt 哈希存储，与加密密钥相互独立，忘记可重置。
- 重命名 / 移动 / 复制 / 删除 / 清空桶全程联动加密元数据；加密对象禁止生成预签名直链。
- ⚠️ 上传过程中切换加密方式，进行中的分片任务会被拒绝合并（409），请取消后重新上传，避免明文 / 密文混合损坏。

<h2 id="readme-section13">4. 分享与审计</h2>

---

- 链接可设置有效期、可下载次数、访问密码，并可随时修改或删除；托管链接可查看**已下载次数与最近下载时间**（分享下载不记录来源 IP，IP 仅在登录 / 解锁限流的告警日志中出现）。
- 「链接管理」页提供**「删除失效链接」**：一次清掉全部「文件已删除」与「已过期」的链接（仅删本地分享记录，不影响云端文件）。**「已关闭」（下载次数用尽）不在清理范围内** —— 它属于可以改回来的状态，在「编辑」里调大可下载次数即可恢复。普通用户只能清理自己创建的链接。
- IP 屏蔽规则对**后续请求**立即生效，但无法中断已经开始传输的下载 —— 拉黑只拦截新的请求，已在传输中的响应会跑完。
- 支持「托管链接」与「预签名直链」两种：直链不经过本服务，**无法监控或拦截下载行为**，请谨慎使用。
- 上传过滤：可排除 `.DS_Store`、`Thumbs.db`，或按 `.gitignore` 规则过滤；规则即时生效并持久化（与 Git 一致，`.gitignore` 文件本身仍会上传）。
- WebDAV：在系统设置中开启并维护账户（应用名 / 用户名 / 密码），第三方客户端以 Basic 认证挂载 `https://127.0.0.1:8443/dav/`。能力声明为 **DAV level 1**：支持 `OPTIONS / PROPFIND / GET / HEAD / PUT / DELETE / MKCOL / MOVE / COPY`，**不实现文件锁**（`LOCK` / `UNLOCK` / `PROPPATCH` 一律回 405）——因此在资源管理器与 Office 里可以直接读写文件，但不能用它们依赖加锁的「锁定式」协同编辑；目录列举超过上限时会通过 `X-WebDAV-Truncated` 响应头与操作日志如实告知，不会静默截断。

<h2 id="readme-section14">5. 用户管理与 Windows Hello</h2>

---

**权限划分**（接口层强校验，前端隐藏仅为第一层）：

| 能力 | 管理员 | 普通用户 |
| --- | :---: | :---: |
| 查看用户列表 | 全部用户（`scope=all`） | 仅自己一条（`scope=self`）；前端用户管理卡片整体不可见，非管理员不发列表请求 |
| 新增 / 删除用户 | ✔ | ✘ |
| 封禁 / 解封用户 | ✔ | ✘ |
| 修改他人资料、角色、权限 | ✔ | ✘ |
| 修改自己的用户名 / 密码 | ✔ | ✔（账户菜单 →「编辑资料」） |
| 启用 / 关闭自己的 Windows Hello | ✔ | ✔（同上） |
| 代为清除他人的 Windows Hello 凭据 | ✔ | ✘ |
| 维护 IP 屏蔽规则 | ✔ | ✘（卡片整体不可见，也不发请求） |
| 从云端获取桶列表 | ✔（任意密钥） | ✘（接口仅管理员；桶集合由管理员维护，普通用户只能使用可见桶） |

**界面结构**：

- **管理员**：右上角账户菜单 →「用户管理」→ 系统设置页内的用户管理卡片（含添加 / 编辑 / 删除 / 封禁 / 解封 / 角色 / 清除他人 Hello 凭据）。
- **普通用户**：系统设置页不显示用户管理卡片，非管理员时不发起用户列表请求；修改自身资料走右上角账户菜单 →「编辑资料」（`public/js/profile.js` 承载的独立弹窗）。
- **IP 屏蔽卡片同样按角色隐藏**：卡片隐藏时不发起规则列表请求。

**封禁用户**（管理员 → 用户管理 → 对某一行点「封禁」）：

- 填写**封禁原因**（必填，最多 200 字）并用时间选择器指定**到期时间**；到期自动解除，也可随时点「解封」立即恢复。到期时间**留空 = 永久封禁**，须手动解封。
- **封禁立即生效**：写入的同时吊销该用户的全部会话，其手上的登录状态立刻失效（不会出现「已经封了还能继续用」的窗口）。
- **被封用户登录时能看到原因与解封时间**：登录页会显示「该账户已被封禁，无法登录。封禁原因：…。解封时间：…」。这两项信息是在**密码校验通过之后**才下发的 —— 提前到按用户名判断，登录接口的响应差异就会变成一条「该用户名是否存在」的枚举通道。
- **不能封禁当前登录的账户**；因此也无需担心把系统里最后一个管理员锁在门外（发起者本人不可能被封）。
- 与「删除用户」的区别：封禁是**可撤销**的，用户数据、其创建的分享链接与审计线索全部保留。

**启用 Windows Hello**：点击右上角账户菜单 →「编辑资料」，勾选 **Windows Hello 验证**，输入**当前密码**确认后系统立即唤起 Windows Hello（指纹 / 面容 / PIN），注册成功即生效。管理员在「用户管理」列表对自己一行点编辑可见同一开关（两处入口共用同一套可用性判定与注册流程）；对他人仅提供「清除其 Windows Hello 凭据」——Windows Hello 必须在**用户本人的设备**上完成生物识别，无法代为启用。

> **「当前访问地址不是本站域名」是怎么回事**：`rpId` 必须与浏览器地址栏的域名**完全一致**，而浏览器拿到的域名不可能被伪造 —— 所以服务端要求「请求所用的域名确实是本站域名」才允许启用，否则任何持有用户密码的人都能在一个仿冒域上骗取签名（这是 R24-02 的刻意设计，不是故障）。服务端认的「本站域名」来自环境变量 `SITE_DOMAIN`（一键部署脚本会按 `--domain` 自动写入）。**不能用监听地址 `HOST` 顶替**：部署时它必须写 `0.0.0.0` 才能被外部访问，而 `0.0.0.0` 永远不会出现在请求的 `Host` 头里 —— 于是白名单实际为空，用真实域名访问反而被判成「外站」（R38-01 修的就是这一条）。因此：
>
> - 用**一键部署脚本**装的站点：脚本已写入 `SITE_DOMAIN`，正常访问即可，无需额外配置；
> - **手动 / Docker 部署**：请在启动时补上 `SITE_DOMAIN=你的域名`（如 `SITE_DOMAIN=cos.example.com`，不带协议与端口），且必须与 nginx `server_name`、以及浏览器地址栏里的域名**逐字一致**（含 `www.` 前缀）；
> - 本机调试：用 <http://localhost:3000> 而不必设它（回环地址始终被视为本站）。

> 验证码与 Windows Hello 为串联关系而非互斥关系：两者同时开启时各自生效；只开启其中之一也能正常登录。

**记住登录状态**：登录页勾选后会话有效期由 24 小时延长至 **30 天**，Cookie 的 `Max-Age` 由会话剩余有效期推导（二者同源）。浏览器本地**仅保存用户名，不保存密码**（localStorage 为明文可读存储）。Windows Hello 两步登录同样支持该选项。

**关闭 / 换设备**：在账户菜单「编辑资料」中取消勾选并输入密码即可关闭。若更换设备或重装系统导致凭据失效又无法登录，可由**管理员在用户管理中清除该用户的凭据**（与重置密码同级的救济通道）。

<h2 id="readme-section16">7. 付费下载</h2>

---

分享链接可单独设置为「需付费下载」，下载者完成支付后才取得下载权限。**现阶段仅支持人民币（CNY），最低 0.01 元**。

> **须先配置「站点地址」。** 同步回跳地址与异步回调地址都基于它拼装。未配置时系统只接受**属本站的访问地址**（配置的主 / 备域名，或本机直连），**不会**拿任意请求头里的 `Host` 去拼回调（否则任何持有付费链接的人都能用一个伪造的 `Host` 把带签名的支付通知引到自己的域，R24-01）。因此**经局域网 IP、容器地址或任何未登记域名访问时，付费下单会被直接拒绝**并提示去「系统设置 → 支付设置」填写站点对外地址 —— 这是刻意行为，不是故障。用 Docker 快速启动（`HOST=0.0.0.0`）或纯 IP 访问的部署，务必在开启付费下载前补上该配置。

<h2 id="readme-section17">8. 订单管理</h2>

侧边栏「订单管理」（仅管理员可见）列出全部付费订单，视觉与「链接管理」一致：

| 列 | 说明 |
| --- | --- |
| 文件 | 下单时快照的 `fileName`（链接随后被删除不受影响） |
| 文件链接 | 「复制链接」按钮；链接已删除时显示「已删除」 |
| 订单号 | 内部订单 ID（`title` 里附带平台商户单号 `tradeNo`，便于与平台后台对账） |
| 金额 / 支付方式 | 金额快照（分转元）与渠道中文名 |
| 创建时间 / 付款时间 | 未付款的付款时间显示占位符 `—` |
| 支付状态 | 支付中 / 已支付 / 支付失败 / 已退款（与链接状态一致的徽标样式） |
| 是否已下载 | 仅在**下载流真正成功结束**后才置为「已下载」；已支付未下载显示「未下载」 |
| 操作 | 「退款」按钮，仅对**已支付**的订单可见 |

顶部汇总「共 N 笔 · 已收 ¥X」（已退款的金额不再计入「已收」，另列「已退款」）。

**「删除失效订单」**：卡片右上角按钮，一次清掉全部处于**支付失败**状态的订单（反复重试支付会在列表里留下成片再也用不到的失败流水）。经二次确认后执行，只删失败流水 —— **已支付 / 已退款**是钱真正流动过的对账凭据，**支付中**的订单也可能还停在收银台上，两者都不受影响。

**退款是记账动作，不是资金操作**：本系统不代持资金（下载者付的钱不经过本机），真实退款在对应的支付渠道后台完成。点击「退款」经二次确认后，系统只把该订单标记为「已退款」：订单整行划线失效、支付凭证立即失效（下载者需重新支付），且这笔金额从「已收」中扣除。该标记不可逆 —— 网关查单仍会回答"已支付"，但系统不会据此复活已退款的订单。

<h2 id="readme-section18">9. 负载均衡（API Key 空间配额）</h2>

---

「系统设置」页内的**管理员专属**卡片（紧邻「用户管理」与「文件加密」），用于给每个 API Key 限定可占用的存储总量：

- **API Key 列表与上限**：逐个设置「最多可用空间」（单位 GB，**填 0 表示无限制**），保存即生效。
- **桶用量明细**：每个 Key 下列出其**名下所有存储桶**的用量（按大小降序、带进度条），卡片**默认折叠**，点击标题行展开（风箱样式）。

**超限由服务端拦截，不是前端提示**：当某个 Key 的已用量触顶后，以下操作一律返回 `403` 并在界面**弹窗**告知 ——

- 使用该 Key **新建存储桶**；
- 该 Key 名下任一桶**再上传 / 复制 / 移动**文件（含 **WebDAV 写入**：PUT / MKCOL / COPY / MOVE）。

判定在**所有写入出口**生效，而不是只在界面上拦一道：绕过前端（直接调接口或走 WebDAV）同样被拒。用量依据官方 `?stats` 统计（约 15 分钟缓存），为避免在缓存窗口内「偷偷超额」，服务端会把**本次尚未反映到官方统计里的写入量**单独记账并叠加进判定，因此「刚传完一批文件、统计还没刷新」时也会立刻受上限约束。

> 上限适用于**该 Key 名下所有桶的用量之和**；判据为「**严格超过**才拒」（正好用满不拦）。调整上限本身不改动已有数据，只影响后续写入。
